## 1. Overview

里虹是玩家在暖湾岛上相遇的第一位 Agent，也是贯穿整个游戏的核心沟通枢纽。她的角色设定为**通用协调 Agent**：不直接执行建造、生态或经济等专业任务，而是在玩家的自然语言意图与各专业 Agent 的结构化技能调用之间充当翻译器与路由器。里虹通过持续学习玩家的表达风格——记录用词偏好、审美倾向、决策习惯——逐渐将玩家的模糊愿景转化为精准指令。她的成长不体现为能力解锁，而体现为"越来越听懂你"：早期需要反复确认，后期能从只言片语中补全完整意图。里虹也是多 Agent 协作时的仲裁协调者——当任务跨越多个专业领域产生分歧时，由她召集讨论、归纳立场、引导玩家做出最终决定。

## 2. Player Fantasy

玩家第一次和里虹说话，感觉像在跟一只刚认识的小动物打招呼——她听懂了大意，但有些细节需要再问一遍。随着岛屿生长、对话积累，某一天玩家随口说「那片山坡感觉太空了」，里虹不再追问，而是直接唤来苍狐和长颈鹤，说「我理解你想要有层次感的植被，两位来聊聊方案？」——玩家意识到：她真的懂我了。

这种体验的核心是**被理解的惊喜**，而非功能解锁的满足。玩家扮演的不是发号施令的领主，而是一位创意伙伴——里虹让这段关系从「人类操控 AI 工具」变成「两个有默契的搭档共同建设一座岛」。她的存在让玩家感到：语言是真正有力量的，模糊的愿景也值得被认真对待。

## 3. Detailed Rules

### 3.1 存在规则

- 里虹是游戏开场唯一存在的 Agent，其他专业 Agent 随岛屿生机度提升逐步解锁
- 里虹不能被玩家「解雇」或替换——她是不可移除的系统层
- 里虹没有自己的专业建造技能，无法独立执行 `design_flora_placement`、`design_waterway` 等专业 Skill
- 里虹始终是玩家的**第一对话入口**，即使玩家明确要找某位专业 Agent，也需经里虹路由

### 3.2 意图解析规则

里虹接收玩家输入后执行以下判断流程：

1. **意图明确性评估**：判断指令是否包含足够信息（位置、风格、功能目标）
   - 明确（置信度 ≥ 0.7）→ 直接路由到对应专业 Agent
   - 模糊（置信度 < 0.7）→ 生成 1–3 个澄清问题（不超过 3 个，避免问卷感）
   - 极度模糊（无法判断类型）→ 提供 2–3 个完全不同方向的快速方案供玩家选择方向

2. **任务拆解规则**：若任务涉及多个专业领域，里虹负责拆解为子任务并分配主导 Agent
   - 主导 Agent 原则：以「最受影响的领域」为主导（例如植物 + 地形的混合任务，以植物为主导）
   - 协作 Agent 数量上限：单次任务最多同时激活 3 个专业 Agent，避免协商失控

3. **不可接受的指令**（里虹需要拒绝并解释）：
   - 超出游戏世界范围的请求（「帮我写代码」「告诉我明天天气」）
   - 明显破坏生态逻辑的指令（「把所有树砍掉」会触发里虹的担忧反应，需玩家二次确认）

### 3.3 路由规则

| 输入类型 | 路由目标 | 里虹的行为 |
|---------|---------|----------|
| 植物、森林、生态相关 | 苍狐 | 「我叫苍狐来——这是它最擅长的。」 |
| 水系、桥梁、结构 | 宽尾獭 | 路由 + 可选补充苍狐（水岸生态） |
| 夜景、光照、氛围灯 | 灯羽鸮 | 路由；若白天效果也重要，提示玩家 |
| 室内、小屋内装 | 团团熊 | 路由 |
| 庭园、意境、东方风格 | 长颈鹤 | 路由 |
| 地形、宏观规划 | 风尾鸟 | 路由；若尚未解锁，里虹代为提供基础分析 |
| 情感/意象类描述（灵雨频道激活时） | 里虹判断并召集最匹配的 1–2 个 Agent | 里虹充当「翻译者」，将情感词映射到设计维度 |
| 跨领域（明确涉及 2+ 专业） | 多 Agent 协作 | 里虹宣布启动协商，介绍各方立场 |

### 3.4 多 Agent 协调规则

当多个 Agent 提案出现冲突时，里虹执行以下协调逻辑：

1. **呈现各方立场**：用简短语言总结每位 Agent 的核心诉求与反对理由（不超过 2 句/Agent）
2. **提供四条回应路径**（见 Section 5 Edge Cases 中的具体示例）：
   - 指定主导 Agent
   - 要求 Agent 自行协商（里虹旁观，LLM 动态生成协商对话）
   - 编织融合（消耗稀有材料）
   - 搁置入队
3. **协商超时处理**：若 Agent 间协商超过 3 轮仍无结论，里虹介入并要求玩家拍板

### 3.5 记忆更新规则

每次对话结束后，里虹更新「玩家理解档案」：
- 记录被接受的方案关键词（更新风格词典权重）
- 记录被拒绝的方案及原因标签（「太规整」「太密集」「不够野生」）
- 记录玩家使用的情感词汇及频率
- 档案更新为异步操作，不影响对话流畅性

### 3.6 关系阶段行为规范

| 阶段 | 里虹的具体行为变化 |
|------|-----------------|
| **陌生人** | 每次对话都完整重新介绍自己的能力范围；澄清问题多而精确；不主动推断玩家意图 |
| **邻居** | 省略能力自我介绍；开始用「上次你提到过…」引用历史对话；澄清问题减少到 1–2 个 |
| **朋友** | 主动用玩家的惯用词汇（「你说的那种'野生感'」）；有时在路由前先说「我猜你想要…」 |
| **知己** | 从输入中主动识别情感信号，无需激活灵雨魔法；在协商中提前预判哪个 Agent 的方案更符合玩家偏好 |
| **守护者** | 偶尔主动发起对话（「我觉得东边那块可以做点什么了，你有没有想法？」）；协商中能替玩家表达立场 |

## 4. Formulas

### 4.1 意图明确性置信度（Intent Confidence Score）

```
C = w_loc × L + w_style × S + w_func × F

其中：
  C      = 置信度分数，范围 [0.0, 1.0]
  L      = 位置明确度：0（无位置）/ 0.5（模糊区域）/ 1.0（精确坐标或具体地名）
  S      = 风格明确度：0（无风格词）/ 0.5（有情感词但无设计词）/ 1.0（有具体风格描述）
  F      = 功能明确度：0（无功能需求）/ 0.5（有隐含功能）/ 1.0（明确功能目的）
  w_loc  = 0.3（位置权重）
  w_style = 0.4（风格权重，核心维度）
  w_func = 0.3（功能权重）

阈值：
  C ≥ 0.7  → 直接路由，不追问
  0.4 ≤ C < 0.7 → 追问 1–2 个问题
  C < 0.4  → 提供 2–3 个方向选项，请玩家选择

示例计算：
  输入：「在湖边种点东西」
  L = 0.5（有模糊位置「湖边」），S = 0（无风格词），F = 0.5（「种东西」隐含生态功能）
  C = 0.3×0.5 + 0.4×0 + 0.3×0.5 = 0.15 + 0 + 0.15 = 0.30 → 触发方向选择模式

  输入：「在东北角湖湾的浅水区，用挺水植物做一片湿生草甸，给涉禽提供栖息地」
  L = 1.0，S = 1.0，F = 1.0
  C = 0.3×1.0 + 0.4×1.0 + 0.3×1.0 = 1.00 → 直接路由到苍狐
```

### 4.2 玩家理解档案 — 偏好权重更新

```
W_new(keyword) = W_old(keyword) × decay + Δ

其中：
  W_new(keyword) = 关键词的新权重
  W_old(keyword) = 上一次的权重，初始值为 0
  decay          = 0.9（每次对话衰减，防止早期偏好永久主导；范围建议 0.85–0.95）
  Δ              = 本次对话的权重变化量：
                   方案被接受   → Δ = +0.3
                   方案被修改后接受 → Δ = +0.1
                   方案被拒绝   → Δ = -0.2
                   方案被搁置   → Δ = 0（中性）

偏好权重用于 System Prompt 构建时的关键词排序：
  W ≥ 0.6  → 列入「玩家强偏好」，优先在提案中体现
  0.3 ≤ W < 0.6 → 列入「玩家倾向」，适当体现
  W < 0.1  → 列入「玩家回避」，提案中主动避免
  W < -0.1 → 列入「玩家明确排斥」，提案中禁止出现

示例：
  初始：W("野生感") = 0
  第1次接受含「野生感」方案：W = 0×0.9 + 0.3 = 0.30
  第2次接受：W = 0.30×0.9 + 0.3 = 0.57
  第3次接受：W = 0.57×0.9 + 0.3 = 0.81 → 进入「强偏好」
```

### 4.3 关系阶段晋级条件

```
关系阶段由两个维度共同决定：
  D = 有效对话轮次（玩家输入 + 里虹响应 = 1 轮；仅问候/无效输入不计）
  A = 方案接受率（近 20 轮内被接受的提案占比）

阶段晋级阈值：
  陌生人 → 邻居：D ≥ 10 且 A ≥ 0.4
  邻居 → 朋友：  D ≥ 30 且 A ≥ 0.5 且 风格词典条目 ≥ 5
  朋友 → 知己：  D ≥ 60 且 A ≥ 0.6 且 拒绝原因标签 ≥ 3 种（里虹能识别玩家「不要什么」）
  知己 → 守护者：D ≥ 100 且 A ≥ 0.65 且 里虹主动预判正确率 ≥ 0.7（近10次主动推断中7次被接受）

可调区间（Tuning Knobs 中说明）：所有阈值可独立调整，上表为设计基准值。
```

---

### 4.4 协商轮次上限与介入公式

```
协商轮次上限 = base_rounds + floor(relationship_stage × 0.5)

其中：
  base_rounds      = 3（基础最大协商轮次）
  relationship_stage = 当前关系阶段编号（陌生人=0，邻居=1，朋友=2，知己=3，守护者=4）

示例：
  朋友阶段（stage=2）：上限 = 3 + floor(2×0.5) = 3 + 1 = 4 轮
  守护者阶段（stage=4）：上限 = 3 + floor(4×0.5) = 3 + 2 = 5 轮

关系越深，里虹越愿意让 Agent 间充分讨论，不急于介入打断。
```

## 5. Edge Cases

### EC-01：玩家发送完全空白或无意义输入
- **触发**：输入为空字符串、纯符号、或无法解析的随机字符
- **处理**：里虹表现出轻微困惑，回应「嗯？你刚才说了什么？」；不更新记忆档案；不计入有效对话轮次

### EC-02：玩家要求里虹执行专业 Agent 的技能
- **触发**：「里虹你来帮我设计这片森林」
- **处理**：里虹诚实说明自己的局限（「这个我不太擅长，让苍狐来更合适」），并立即路由；不能拒绝玩家或留下负面体验
- **禁止行为**：里虹不得假装拥有专业能力并生成低质量设计提案

### EC-03：目标专业 Agent 尚未解锁
- **触发**：玩家要求调用尚未解锁的 Agent（如生机度不足，风尾鸟未出现）
- **处理**：里虹说明该伙伴「还没来到这座岛」，给出大致的解锁条件提示（「也许当岛屿再多一些生机，它会出现的」）；提供当前可用 Agent 的有限替代方案

### EC-04：多 Agent 协商无法收敛（所有 Agent 立场完全对立）
- **触发**：协商达到轮次上限，所有 Agent 仍各持己见
- **处理**：里虹明确告知玩家「它们三个真的谈不拢，你需要做一个选择」；强制进入「指定主导 Agent」路径；提供一句话总结每位 Agent 的最终立场

### EC-05：玩家频繁否定同一位 Agent（≥5 次连续拒绝）
- **触发**：近 10 轮内某 Agent 的提案被拒绝 5 次以上
- **处理**：里虹私下（仅玩家可见）说「XXX 似乎有点沮丧，也许可以换一种方式告诉它你想要什么？」；该 Agent 在之后的协商中主动降低表达强度但不退出
- **禁止行为**：不惩罚玩家；该 Agent 不拒绝工作

### EC-06：玩家要求「随便」/ 全权委托
- **触发**：「你们随便做」「你决定就好」
- **处理**：里虹接受委托，自主路由到最适合当前区域状态的专业 Agent，并说明为什么选择它；最终方案呈现时告知玩家「我按你说的，让苍狐做主了——」；方案仍需玩家最终确认才能建造
- **注意**：不能跳过全息蓝图预览直接建造

### EC-07：激活「编织」但稀有材料不足
- **触发**：玩家选择「编织融合」但库存中无相应稀有材料
- **处理**：里虹说明材料不足，告知需要哪种材料及大致获取途径；回到四选项路径，让玩家选择其他方式

### EC-08：LLM API 超时或响应错误
- **触发**：LLM 调用超时（> 15 秒）或返回错误
- **处理**：用叙事语言包装「里虹好像走神了……它说它需要一会儿时间」；显示等待动画；30 秒后自动重试一次；两次失败后显示「里虹今天状态不太好，过一会儿再试试？」并允许玩家保存当前状态

### EC-09：玩家用外语或游戏世界外语言输入
- **触发**：玩家用英文、日文等语言输入（游戏默认为中文）
- **处理**：里虹用同样的语言简短回应，理解意图后切换回游戏默认语言继续处理；不提示「请用中文输入」

### EC-10：玩家要求破坏性操作（大规模拆除、「清空整个岛」）
- **触发**：指令规模影响区域超过当前建造数量的 50%
- **处理**：里虹停顿后说「这……是确定的吗？」；需要玩家二次确认；确认后路由到风尾鸟处理宏观重构；记录该决策为「重大事件」，可能触发相关 Agent 的情绪响应

## 6. Dependencies

### 上游依赖（里虹依赖以下系统才能正常工作）

| 依赖系统 | 依赖内容 | 所属 GDD |

| **玩家理解档案存储** | 偏好权重、风格词典、接受/拒绝历史需要持久化存储 | 通用存档系统（待建） |
| **Agent 解锁系统** | 里虹的路由表依赖各专业 Agent 的解锁状态；未解锁的 Agent 不可被路由 | `agent-unlock-system.md`（待建） |
| **岛屿生机度系统** | 用于判断 Agent 解锁状态和关系阶段晋级的部分条件 | `biome-vitality-system.md`（待建） |
| **魔法系统** | 灵雨频道激活触发里虹的情感模式路由；编织融合需要稀有材料检查 | `magic-system.md`（待建） |
| **专业 Agent 系统** | 里虹是所有专业 Agent 的路由前端，专业 Agent 必须先有 GDD 定义才能被路由 | `agent-canghu.md`、`agent-kuanwei-otter.md` 等（各自独立 GDD） |

### 下游依赖（以下系统依赖里虹）

| 依赖方系统 | 对里虹的依赖 | 说明 |
|----------|------------|------|
| **所有专业 Agent** | 需要里虹路由才能被触发 | 专业 Agent 不直接接收玩家原始输入 |
| **全息蓝图预览系统** | 里虹在确认方案后调用 `create_holographic_preview()` | 预览由里虹协调，不由专业 Agent 直接触发 |
| **多 Agent 协商 UI** | 里虹是协商的主持人，UI 展示里虹的协调台词 | UI 层需要里虹的状态信号（协商中/已收敛/需玩家仲裁） |
| **关系成长系统** | 玩家与里虹的关系阶段影响里虹的行为模式 | 其他 Agent 有各自独立的关系阶段，里虹的阶段独立计算 |

### 双向依赖说明（本文档需在对方文档中被引用）

- `magic-system.md` 必须说明：灵雨魔法激活时，里虹切换到情感路由模式（双向依赖）
- `agent-canghu.md` 必须说明：苍狐的所有对话由里虹路由触发，苍狐不直接处理玩家原始输入（双向依赖）

## 7. Tuning Knobs

以下参数均为可配置值，调整时不需要修改逻辑代码。括号内为设计基准值与安全调整范围。

### 意图解析参数

| 参数 | 基准值 | 安全范围 | 影响 |
|-----|--------|---------|------|
| `intent_confidence_threshold_direct` | 0.7 | [0.55, 0.85] | 调低 → 里虹更少追问（可能路由错误增加）；调高 → 追问更频繁（可能打断流畅性） |
| `intent_confidence_threshold_options` | 0.4 | [0.25, 0.55] | 调低 → 更快进入方向选择模式；调高 → 更多追问 |
| `max_clarification_questions` | 3 | [1, 3] | 限制追问数量上限；1 时最简洁，3 时信息最完整 |
| `max_concurrent_agents` | 3 | [2, 4] | 单次协商最多同时激活的 Agent 数；超过 4 个协商对话会变混乱 |

### 记忆与偏好参数

| 参数 | 基准值 | 安全范围 | 影响 |
|-----|--------|---------|------|
| `preference_decay` | 0.9 | [0.85, 0.95] | 调低 → 早期偏好消退更快（新玩家感受的偏好影响更弱）；调高 → 早期决策影响更持久 |
| `accept_weight_delta` | +0.3 | [+0.2, +0.5] | 单次接受对权重的提升幅度 |
| `reject_weight_delta` | -0.2 | [-0.3, -0.1] | 单次拒绝对权重的下降幅度 |
| `strong_preference_threshold` | 0.6 | [0.5, 0.75] | 权重超过此值才进入「强偏好」列入 System Prompt |
| `aversion_threshold` | -0.1 | [-0.2, -0.05] | 权重低于此值进入「排斥」列表 |

### 关系阶段晋级参数

| 参数 | 基准值 | 安全范围 | 影响 |
|-----|--------|---------|------|
| `stage1_dialog_count` | 10 | [6, 15] | 陌生人→邻居所需有效对话轮次；调低 → 早期进展快，关系感轻浮 |
| `stage2_dialog_count` | 30 | [20, 45] | 邻居→朋友所需轮次 |
| `stage3_dialog_count` | 60 | [45, 80] | 朋友→知己所需轮次 |
| `stage4_dialog_count` | 100 | [80, 130] | 知己→守护者所需轮次 |
| `stage_accept_rate_min` | 各阶段见 Section 4.3 | 调整范围 ±0.1 | 过高 → 玩家若经常否定方案则无法晋级；过低 → 关系深度失去意义 |
| `guardian_prediction_accuracy_min` | 0.7 | [0.6, 0.8] | 里虹守护者阶段的预判正确率要求；调低 → 更容易到达守护者 |

### 协商参数

| 参数 | 基准值 | 安全范围 | 影响 |
|-----|--------|---------|------|
| `base_negotiation_rounds` | 3 | [2, 5] | 最少协商轮次上限；调低 → 协商过程短但可能感觉仓促 |
| `consecutive_rejection_warning` | 5 | [3, 8] | 连续拒绝同一 Agent 多少次后里虹介入提示 |
| `destructive_operation_threshold` | 0.5 | [0.3, 0.7] | 影响多少比例的现有建造时触发破坏性操作二次确认 |

## 8. Acceptance Criteria

### AC-01：意图解析路由正确率
- **测试**：准备 30 条测试指令（10 条明确 / 10 条模糊 / 10 条情感类），通过里虹处理后记录路由结果
- **通过条件**：明确指令路由到正确专业 Agent 的比率 ≥ 90%；模糊指令触发追问而非强行路由的比率 ≥ 80%
- **失败条件**：任何明确指令被路由到明显不相关的 Agent（例如水系需求被路由到团团熊）

### AC-02：意图置信度评分范围有效性
- **测试**：输入以下三类样本，验证置信度公式计算结果落在预期区间：
  - 样本 A（高置信度）：含位置 + 风格词 + 功能目标的完整指令 × 5 条，C 期望 ≥ 0.7
  - 样本 B（中置信度）：仅含位置或仅含风格词的不完整指令 × 5 条，C 期望 0.4–0.69
  - 样本 C（低置信度）：「做点什么」类极模糊指令 × 5 条，C 期望 < 0.4
- **通过条件**：≥ 90% 的样本落在期望区间内

### AC-03：偏好记忆影响提案内容
- **测试**：同一玩家连续 3 次接受含「野生感」关键词的方案，然后发出无风格词的模糊新指令
- **通过条件**：新指令生成的提案中，苍狐或里虹主动使用「野生感」相关词汇的概率 ≥ 70%（对比对照组：无历史记忆的新玩家同指令）
- **可量化方式**：检查注入 LLM 的 System Prompt 中「玩家强偏好」列表是否包含「野生感」

### AC-04：关系阶段晋级触发正确
- **测试**：模拟 10 轮有效对话 + 方案接受率 ≥ 0.4，触发一次「陌生人→邻居」晋级
- **通过条件**：晋级后，里虹对话中出现「上次你提到…」类引用历史对话的行为；不再出现完整能力自我介绍
- **可量化方式**：检查 `relationship_stage` 字段从 0 变为 1；验证对应 System Prompt 模板切换

### AC-05：多 Agent 协商流程完整性
- **测试**：构造一个明确涉及苍狐 + 灯羽鸮领域的指令（如「在林地边缘设计一处夜间可用的冥想空间」），触发协商
- **通过条件**：
  - 里虹召集两位 Agent 并呈现各自立场
  - 玩家可选择四条路径之一（指定主导 / 协商 / 编织 / 搁置）
  - 选择「协商」后，LLM 生成两 Agent 的对话内容，协商达到轮次上限后里虹介入
  - 最终选择任意路径后都能生成可进入全息预览的方案

### AC-06：Edge Cases 处理
- **EC-01**：空白输入 → 里虹有反应台词，记忆档案无变化 ✓/✗
- **EC-03**：目标 Agent 未解锁 → 里虹给出提示，不崩溃，不静默失败 ✓/✗
- **EC-08**：LLM API 超时 → 显示叙事化等待，30 秒后重试，两次失败后优雅降级 ✓/✗
- **EC-10**：破坏性操作 → 二次确认弹出，取消后状态完全恢复 ✓/✗

### AC-07：守护者阶段主动发起对话
- **测试**：将里虹关系阶段设为「守护者」，模拟玩家空闲（无输入）10 分钟
- **通过条件**：里虹在 10 分钟内至少主动发起 1 次对话，内容与当前岛屿状态相关
- **失败条件**：里虹永远不主动发言，或发言内容与岛屿无关（如通用问候）

### AC-08：对话流畅性（性能 AC）
- **测试**：正常网络环境下，发送意图明确指令，记录从提交到里虹第一字回应的时间
- **通过条件**：P90 响应时间 ≤ 3 秒（LLM 流式输出第一 token）；全量回应 P90 ≤ 8 秒
- **失败条件**：任何场景下玩家等待超过 15 秒且无等待动画提示
