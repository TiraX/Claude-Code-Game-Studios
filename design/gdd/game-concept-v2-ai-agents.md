## 一、范式声明：从「执行者」到「创意总监」

### v1 的玩家定位
> 你是一个会魔法的建造者——亲手种下每一棵树，亲手施放每一道魔法。

### v2 的玩家定位
> 你是一个有梦想但「手不灵巧」的创意总监——你有画面感，但你需要专业伙伴来实现它。你的核心技能不是「会建造」，而是**会表达、会沟通、会协调**。

### 这个转变带来了什么

这是一个在游戏史上几乎没有被探索过的核心体验：

**不是「我怎么建造这个」，而是「我怎么把脑子里的东西说清楚」**

沟通能力本身就是成长曲线。早期玩家的语言是模糊的，Agent 理解有限，结果充满惊喜和意外；随着关系加深，Agent 开始「懂你」，提案越来越贴近你的直觉。这是真正属于 AI 时代的情感成长——不是数值进度条，而是一个 AI 真的在理解你。

## 二、动物 Agent 系统

### 2.1 核心设计原则

每位动物伙伴不只是「功能按钮」，而是一个有专业知识、独特审美偏见、可成长记忆的 **AI Agent**。

**三条铁律：**
1. **专业边界是真实的** — Agent 的局限不是设定上的借口，而是真正的能力范围。苍狐确实不擅长室内设计。
2. **个性局限是游戏内容，不是障碍** — 玩家需要学会如何与各自有「偏见」的 Agent 协作，而不是等待一个完美助手。
3. **成长是真实的学习，不是数值解锁** — Agent 通过对话记忆逐渐理解玩家偏好，提案质量的提升源于关系深度，而非「升级」事件。

---

### 2.2 核心 Agent 名册

| 动物伙伴 | 专业领域 | 审美偏见 | 典型「局限」 |
|---------|---------|---------|------------|
| **里虹**（虹灵鼠） | 通用协调 + 任务拆解 | 好奇多变、什么都想碰 | 没有深度专业，有时会把任务拆解过细或想法天马行空 |
| **苍狐**（白狐） | 森林生态 + 植物群落 | 极简主义，偏爱留白 | 永远觉得建造太多，会「反对」大规模改造 |
| **宽尾獭** | 水系工程 + 结构建造 | 实用主义，看重耐久 | 美学敏感度低，容易出现「功能合理但不好看」的方案 |
| **灯羽鸮**（猫头鹰） | 夜间景观 + 光照设计 | 神秘浪漫，偏爱阴影层次 | 提案默认适合夜间，白天效果有时被忽视 |
| **长颈鹤** | 东方庭园 + 意境空间 | 追求意境与留白，忌繁复 | 提案「意境」有余，「实用性」不足，很难容纳工坊类建筑 |
| **团团熊** | 舒适内装 + 家居设计 | 北欧治愈风，偏爱温馨拥挤 | 方案总是塞得有点满，室外空间处理能力弱 |
| **风尾鸟** | 地形塑造 + 岛屿宏观规划 | 宏观视角，重视整体结构 | 对细节不感兴趣，「这片区域的功能定位」比「那朵花种哪里」更在乎 |

**里虹的特殊地位：**
里虹是唯一从游戏开始就存在的伙伴，也是玩家与其他 Agent 之间的「翻译层」。当玩家的指令不够清晰时，是里虹在问「你是指那种野生感，还是有设计感的野生感？」——它的成长表现为越来越准确地理解玩家语言，而不仅仅是把任务分出去。

---

### 2.3 Agent 个性成长曲线

成长分五个关系阶段，每阶段的变化体现在**提案风格**和**沟通方式**上：

**以苍狐（森林生态 Agent）为例：**

| 关系阶段 | 苍狐的典型行为 |
|---------|--------------|
| **陌生人** | 「我负责植物配置。建筑和地形不在我的领域。如果你要我做其他事，请找对应的伙伴。」（边界感强，几乎不主动提问） |
| **邻居** | 开始问「你更倾向密林还是疏林？」——开始主动收集偏好信息 |
| **朋友** | 「上次你说的那个'野生感'，我的理解是这样——」（开始引用玩家的用词，说明自己的理解） |
| **知己** | 「你喜欢有点拥挤的感觉，但我坚持要留出生态廊道。我做了一个妥协方案，你看看是否接受？」（第一次主动提出对抗性妥协） |
| **守护者** | 苍狐的方案里开始自发留下玩家最喜欢的那种角落——不再需要玩家说「我想要…」，它已经预判了 |

**跨 Agent 的一致性原则：**
每个 Agent 的成长路径由三个轴构成：
- **理解深度**：从字面理解到风格理解再到情感理解
- **主动程度**：从被动响应到主动预判
- **协作意愿**：从坚守边界到跨领域主动提议联合方案

---

### 2.4 Agent 的 Skill 注册表

每个 Agent 可以调用的技能（Skills）——这也是游戏后端的技术接口：

**通用 Skills（所有 Agent 可调用）：**
```
analyze_area(location, radius)           → 返回区域信息（地形、现有植物、生机度）
get_player_preference_profile()          → 返回玩家历史偏好记录
generate_design_proposal(spec, count)    → 生成 N 个方案（文字 + 平面布局描述）
request_3d_generation(design_spec)       → 调用 3D 生成 API
place_model(model_id, position, scale)   → 将生成模型放置到世界中
create_holographic_preview(layout)       → 在游戏世界生成全息蓝图预览
```

**专业 Skills（各 Agent 专属）：**
```
# 苍狐（森林生态）
analyze_ecosystem_health(area)
design_flora_placement(style, density, succession_stage)
calculate_biodiversity_index(plant_list)
suggest_ecological_corridors(from_area, to_area)

# 宽尾獭（水系建造）
design_waterway(start_point, end_point, style)
calculate_water_flow(terrain_data)
design_bridge(span, material, load_type)
analyze_flood_risk(area)

# 灯羽鸮（光照景观）
design_lighting_layout(area, time_preference)
calculate_shadow_map(time_of_day, vegetation)
design_night_garden(bloom_species, glow_elements)

# 团团熊（舒适内装）
design_interior_layout(building_size, resident_type)
suggest_furniture_arrangement(space_spec)
calculate_coziness_score(room_design)
```

### 2.5 多 Agent 协作与分歧系统

这是 v2 中**成本最低、深度最高**的玩法层——由 LLM 动态生成，每次对话都不同。

**分歧触发条件：**
当任务涉及多个 Agent 的专业领域时，里虹会自动召集相关 Agent 进行「协商」。

**分歧示例：**

> 玩家：「我想在湖边建一个什么都有的区域。」
>
> 苍狐：「湖边应该保持以原生植物为主。任何建造都需要最小化干扰。」
> 宽尾獭：「正好，我可以设计一个融入水系的栈道区，不破坏湖岸。」
> 灯羽鸮：「如果要全功能，夜间也应该能使用。我可以加萤火虫花园作为自然光源。」
> 苍狐：「我反对。人工引导萤火虫会影响湖边的生态平衡，而且光污染会抑制我选择的夜花植物。」
>
> 里虹：「它们三个意见不合。你想让我帮你协调，还是你来定夺？」

**玩家的四种回应路径：**
1. **指定主导**：「苍狐优先，其他配合它。」→ 生成以生态优先的方案
2. **要求讨论**：「让它们自己商量一个妥协方案。」→ 触发 Agent 间对话，由 LLM 动态生成协商过程
3. **编织融合**：消耗稀有魔幻材料，强行融合所有方案 → 结果有惊喜但也有不可预期的「化学反应」
4. **搁置**：「先放一放。」→ 任务进入「悬置队列」，等待更多 Agent 加入或生机度提升后再议

**分歧对关系的影响：**
- 每次协商后，参与 Agent 会记录「这次玩家的选择倾向」
- 如果玩家总是支持某个 Agent 的立场，其他 Agent 会开始调整自己的提案风格来更贴近玩家
- 频繁被否定的 Agent 会在对话中表达「失落」——但不会惩罚玩家，只是情感色彩变化

## 三、玩家 × Agent 交互系统

### 3.1 对话界面设计原则

- **纯文字聊天**，融入游戏 UI 中（而非独立弹窗）
- 对话发生在游戏世界里，像「对着伙伴说话」而不是「打开聊天软件」
- 里虹是默认对话入口，其他 Agent 可以直接「走过来」加入对话
- **不显示 LLM 的技术性限制**（如 token 用尽、API 错误）——用叙事语言包装：「里虹今天有点心不在焉，它说需要休息一下」

---

### 3.2 指令质量与「沟通成长」

玩家的表达清晰度会影响提案质量——这不是惩罚，而是游戏性的一部分：

**模糊指令 → 多方案 + 里虹追问：**
> 玩家：「做点什么」
> 里虹：「这里……做点什么是指？我有三个想法，但不确定你的方向。」
> （里虹提出三个完全不同方向的快速方案供选择）

**精确指令 → 高质量单方案：**
> 玩家：「在东坡山脊线上，用野生苔藓和碎石做一条蜿蜒小径，宽度刚好一人通过，不要任何人工灯光」
> 苍狐：「这非常适合我。我开始设计了。」
> （直接生成一个方案，细节质量更高）

**情感指令（灵雨魔法频道）**：
> 玩家激活「灵雨」后输入：「我想要一个下雨天也让人觉得安全的地方」
> 里虹：「嗯……我去问问团团熊和灯羽鸮。这种感觉需要它们两个一起来。」

**关键设计：玩家不会被教「怎么说话」，而是在与 Agent 的互动中自然学会如何表达。**

---

### 3.3 魔法作为「沟通频道」的重新定义

| 魔法名 | 沟通模式 | 触发效果 |
|--------|---------|---------|
| **聆绿** | 倾听模式 | 向 Agent 询问当前区域的「状态读取」——「这片地现在适合什么？」Agent 基于 `analyze_area()` 给出诊断 |
| **催芽** | 加速指令 | 要求 Agent 优先处理当前任务，跳过迭代，直接给出「最佳单一方案」 |
| **灵雨** | 情感频道 | 允许用情感/意象下指令而非理性描述，Agent 会尝试「翻译」这种感性需求 |
| **编织** | 融合指令 | 要求多个 Agent 合并提案，消耗稀有材料，结果不完全可预期 |

---

### 3.4 对话记忆与「懂你」进度

**每个 Agent 维护独立的「玩家理解档案」**，包括：

- **风格词典**：从对话中提取的玩家常用词（「野生感」「被包裹」「不要太整齐」）
- **接受/拒绝历史**：哪类方案被接受，哪类被修改，哪类被直接否定
- **偏好权重**：密林vs疏林、功能性vs美观性、复杂vs简洁等维度的估算值
- **情感信号**：玩家用的情感词频率（「喜欢」「讨厌」「不确定」）

**这些档案影响提案生成的 System Prompt**，不是独立的数值系统，而是自然融入 LLM 的上下文中。

## 四、AI 3D 生成系统

### 4.1 生成范围边界

**允许生成（程序化 + AI 生成）：**
- 单体自然物件（特定树木形态、岩石组合、花丛、苔藓块）
- 建筑装饰细节（门廊、窗台、石阶、围栏段落）
- 功能性结构（简单的亭子、栈道段、矮墙）
- 地形微元素（小土丘、浅水潭边缘、草地纹理变化）

**不允许生成（手工制作保证质量）：**
- 动物角色模型（里虹和所有 Agent 伙伴）
- 主角精灵
- 核心叙事道具（传说碎片、灵级材料）
- 主要建筑主体框架（使用预制模板 + AI 变体细节）

**边界原则：** Agent 的「脸」不能是 AI 生成的——情感质量必须被人工保证。场景中的「世界」可以是 AI 生成的。

---

### 4.2 叙事化不完美系统

AI 生成质量的参差不是技术缺陷，而是**游戏中最有意义的成长时刻**。

| 模型状态 | 视觉表现 | 触发条件 | 叙事解释 |
|---------|---------|---------|---------|
| **初降** | 半透明轮廓，略显粗糙，魔力粒子环绕 | 刚生成放置 | 「魔法还在成形中，它还不知道自己应该是什么样子」 |
| **凝聚** | 不透明，细节可见但略显粗糙，颜色偏灰 | 区域生机度达到放置时的 1.5 倍 | 「岛屿的魔力开始注入它，它有了自己的重量」 |
| **苏醒** | 完整细节，材质清晰，颜色饱和 | 区域生机度达到放置时的 3 倍 | 「它已经成为这座岛屿的一部分，不可分割」 |
| **共鸣** | 表面偶有魔力光纹流动，与设计它的 Agent 风格呼应 | 该 Agent 关系达到「朋友」级以上 | 「某个人的心意已经融入它了，这里有它留下的东西」 |

**关键体验时刻：**
当一个放置了很久的「粗糙石亭」在某天清晨突然「苏醒」，变得细腻完整——玩家甚至可能没有意识到岛屿生机度已经悄悄积累到了那个阈值。这是一个不被提醒的惊喜奖励。

---

### 4.3 设计提案的呈现层次

Agent 的设计方案分三层逐步呈现，让玩家在「看到3D结果」之前有充分的确认机会：

```
层 1：文字描述方案
  「我建议在北坡用三丛不同高度的山茱萸形成层次，
   中间留出一块草地供小动物活动，
   最里面是一棵已经有点年纪的老松。」

         ↓ 玩家确认「继续」

层 2：全息蓝图预览（游戏内 AR 式投影）
  半透明的平面布局在实际地形上投影
  Agent 站在旁边，可以对蓝图逐点解释
  玩家可以走进蓝图「感受」空间感
  支持「把那棵松往左移点」的口语调整

         ↓ 玩家确认「建造」

层 3：调用 3D 生成 API
  生成结果以「初降」状态落入世界
  消耗对应魔幻材料
  Agent 有「期待」情绪的反应台词
```

### 4.4 技术 API 选型考量（待定）

| API 候选 | 优势 | 劣势 | 适用范围 |
|---------|------|------|---------|
| Meshy AI | 游戏资产优化好，速度快 | 风格化能力有限 | 自然物件、建筑配件 |
| Tripo3D | 风格迁移能力强 | 成本较高 | 特殊风格化建筑 |
| Hyper3D | 质量较高 | 生成时间长 | 重要的叙事性道具 |
| Luma AI Genie | 生态内容效果好 | API 稳定性待验证 | 有机自然形态 |

**统一原则：** 生成结果必须在游戏引擎内可以实时调整 LOD 和材质，适应「初降→苏醒」的状态过渡。

## 五、核心游戏循环（v2 更新版）

### 即时循环（30秒）
> 对里虹说一句话 → 它问了一个问题 → 你回答 → 它叫来了苍狐 → 苍狐给出了方案描述 → 你说「可以」

*这个「说话—理解—方案」的节奏必须在没有任何视觉奖励的情况下就令人愉悦。*

### 短期循环（5-15分钟）
> 方案通过全息蓝图预览 → 你走进蓝图感受空间 → 微调一个细节 → 确认建造 → 看着粗糙模型「初降」落入世界 → 里虹跑去绕着它转 → 想继续做下一块区域

### 会话循环（30-90分钟）
> 一个 Agent 提出方案 → 另一个 Agent 表示异议 → 三个 Agent 开始讨论 → 你最终做出取舍 → 建造落地 → 生机度提升 → 一个新的影子出现在岸边

### 长线进度（数周/数月）
- **Agent 理解成长**：早期里虹问很多问题；后期苍狐直接说「我知道你想要什么了」
- **岛屿演变**：荒地 → 草甸 → 林地 → 生境 → 传说之岛（与 v1 一致）
- **「苏醒」时刻积累**：越来越多的建造完成最终苏醒，岛屿整体品质层级提升
- **传说碎片解锁**：由聆绿魔法与 Agent 的联合探索逐渐拼合（与 v1 一致）

## 六、技术架构概要

```
玩家文字输入
    ↓
LLM 主推理层（如 GPT-4o / Claude 3.7 Sonnet）
    ├── 意图解析 → 确定任务类型 + 主导 Agent
    ├── Agent 路由 → 激活对应 Agent 的 System Prompt + 记忆上下文
    ├── Agent 间协商逻辑 → 触发多 Agent 对话
    ├── Skill 调用 → analyze_area / design_proposal / 等
    └── 对话输出 → 玩家看到的台词
    
Agent 记忆层（持久化存储）
    ├── 玩家风格词典（per Agent）
    ├── 接受/拒绝历史
    └── 关系阶段状态
    
方案确认后 → 3D 生成 API
    ├── design_spec（由 LLM 结构化生成，包含形态/风格/材质要求）
    ├── 生成调用（Meshy / Tripo3D / 等）
    ├── 模型接收 + 引擎导入
    └── 以「初降」状态放置 + 注册到生机度监听系统

生机度监听系统
    └── 模型苏醒状态机（初降 → 凝聚 → 苏醒 → 共鸣）
```

**引擎选择：Unreal Engine 5**（沿用 v1 决策，Lumen 光照适配叙事化不完美的视觉演变）

**网络需求：**
- LLM API 调用（需要实时网络，延迟需设计缓冲动画）
- 3D 生成 API 调用（异步，玩家可继续对话或探索岛屿）
- 存档数据：本地为主，生成模型资产需要云端缓存策略

## 七、v1 → v2 变化总结

### 保留不变
- 世界观：孤岛、魔力衰退、自然精灵、里虹（虹灵鼠）
- 四种核心魔法名称（功能重新定义）

- 岛屿生机度系统与演变阶段
- 动物关系五阶段（陌生人→守护者）
- 四个游戏支柱（生态优先、有情生命、从容节奏、有机绽放）
- 奖励哲学（印记系统、世界即奖励）
- 美术风格参考（Sky光遇光影质感 + 宫崎骏自然细节）

### 根本改变
| v1 | v2 |
|----|-----|
| 玩家亲手建造（执行乐趣） | 玩家委托 Agent 建造（表达乐趣 + 协调乐趣） |
| 静态动物伙伴（功能 + 故事） | AI Agent（动态记忆 + 个性成长 + 专业能力） |
| 手工精细控制的3D资产 | 生成式3D资产 + 叙事化不完美系统 |

| 单向从玩家到世界的创造 | 玩家 ↔ Agent ↔ 世界的三方共创 |

## 八、新版 MVP 定义

**核心假设（v2）**：玩家用自然语言描述一个想法，里虹和一位专业 Agent 将它转化为可见的设计提案，玩家修改一次后确认，看到粗糙的生成结果「初降」落地——这整个流程必须在10分钟内完成，且让玩家想要「再试一次」。

### MVP 必须包含

1. **里虹（通用 Agent）** — 接收输入、拆解意图、分发任务、主导对话
2. **苍狐（专业 Agent）** — 一个有完整个性局限和基础成长记忆的专业 Agent
3. **`analyze_area` + `generate_design_proposal` + `create_holographic_preview` Skills** — 核心提案流程
4. **全息蓝图预览** — 可在游戏世界中投影、可口语调整的方案预览
5. **一个 3D 生成 API 集成** — Meshy 或 Tripo3D，支持「初降」状态放置
6. **叙事化不完美系统** — 初降/凝聚/苏醒三阶段，与生机度联动
7. **一片可操作的岛屿区域** — 足够承载 2-3 次建造循环
8. **里虹的基础记忆** — 能记住玩家至少 3 次选择倾向并在提案中体现

### MVP 明确不包含

- 多 Agent 分歧协商系统（需要更复杂的多 Agent 协调逻辑）
- Agent 关系五阶段的完整成长曲线（MVP 只需验证「记忆影响提案质量」）
- 完整魔幻材料体系（散级材料作为建造消耗即可）
- 「共鸣」状态（苏醒已足够验证核心体验）

## 九、设计风险 × 开放问题

### 核心风险

**风险 1：LLM 延迟破坏节奏**
- 问题：LLM 调用 + 3D 生成可能需要 10-30 秒
- 缓解：设计充分的等待动画（「苍狐在思考中，它蹲下来画草图…」）；3D 生成设计为异步，玩家可以继续对话

**风险 2：Agent 「出戏」（LLM 给出不符合角色的回应）**
- 问题：LLM 可能输出过于通用、缺乏个性的回应
- 缓解：每个 Agent 需要精心设计的 System Prompt + Few-shot 示例；需要设计「出戏检测」机制

**风险 3：玩家「不会说话」导致挫败感**
- 问题：部分玩家可能不习惯用自然语言描述需求
- 缓解：里虹作为「引导性追问者」帮助玩家澄清需求；保留「随机给我设计一个」的一键模式作为保底

**风险 4：3D 生成质量难以控制**
- 问题：AI 3D 生成的风格一致性目前仍是行业难题
- 缓解：严格定义生成范围（只生成「自然有机形态」的物件，减少人工建筑的生成占比）；叙事化不完美系统为质量参差提供叙事保护

### 开放问题（需要原型验证）

- **Q1**：玩家与 Agent 的对话「一来一回」需要几轮才会感到满足？最长可接受几轮才开始不耐烦？
- **Q2**：全息蓝图预览是「看」就足够，还是必须支持「走进去感受空间感」才有效？
- **Q3**：Agent 分歧时，玩家做出「不公平」的裁决（总是否定同一个 Agent）是否应该触发情绪反应？触发多少次之后？
- **Q4**：3D 生成的「初降」粗糙感在玩家测试中是感到惊喜，还是感到不适？（这是最大的未知量）
